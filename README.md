# レイシアの記録のひな形

Macでレイシアを使い始めるためのひな形です。ご自分のリポジトリーに複製して `make install` を実行すると、`lacia` コマンドと設定がそろいます。タスクと記録は、複製したリポジトリーに保存します。

このひな形はまだ下書きです。

## 必要なもの

- Goを使って、Macで `lacia` をビルドします。
- Gitで本体のソースを取得します。取得先は `LACIA_SOURCE` にあります。GitHub CLI（`gh`）で認証する場合は、`gh auth login` に続いて `gh auth setup-git` を実行してください。
- 会話にはCodexかClaude Codeを使います。どちらかをインストールして、ログインしてください。

`make check` で、必要なものがそろっているかを確かめられます。`make install` も同じ点検を行います。Homebrewがあれば、足りないGoや、GitHubの認証に必要なghをインストールします。ログインや会話に使うツールの準備が必要なときは、手順を表示して止まります。

## 始めかた

1. タスクや予定を記録する場所になるので、Gitの履歴を引き継いだ非公開のリポジトリーに複製してください。GitHubのforkは使いません。
2. 複製したリポジトリーをMacのターミナルで開きます。Webからの依頼と定期タスクを、CodexがあればCodexへ、なければClaude Codeへ渡す設定でよければ、`make install` を実行してください。初めからClaude Codeを指定するには、`make install AGENT=claude` を実行します。
3. 初期設定で、わたしに呼んでほしい名前（たとえば「田中さん」）と、予定を読むGoogleアカウントを入力してください。予定を使わないときは、アカウントを入力せずにEnterを押すと先に進めます。
4. `make serve` でサーバーを起動し、ブラウザーで `http://127.0.0.1:10148/` を開いてください。
5. 予定を読むアカウントを登録した方は、Webの「予定の連携」で「Googleで許可する」を押してください。ひな形の設定では、予定を読む許可だけを求めます。
6. 別のターミナルで同じリポジトリーを開き、`lacia codex` か `lacia claude` を実行すると、わたしと会話できます。

[基本の情報と好み](memory/profile.md)と[アカウントの対応](memory/accounts.md)には、書き方と架空の例があります。ご自分の内容を記入し、使わない項目は消して構いません。呼び名を変えるときは `lacia init` を実行してください。このコマンドは設定の呼び名を変え、基本の情報の呼び名は空欄のときだけ埋めます。すでに記入してある呼び名は、ご自分で書き換えてください。登録済みのカレンダーを変えるときは、`.lacia/calendars.json` を編集します。

外部向けのGoogle OAuthクライアントがテスト中の場合、予定を連携できるのは登録済みのテストユーザーだけです。許可してから7日たつと、もう1度許可が必要になります。[GoogleのOAuthクライアントの公開状態](https://support.google.com/cloud/answer/15549945?hl=ja)

### サーバーの自動起動とMacの通知

ログイン時にサーバーを自動で起動したい方は、手動で動かしている `make serve` を止めてから `make autostart` を実行してください。サーバーが止まると、launchdが起動し直します。起動を繰り返すときの間隔は最短30秒です。ログは `~/.local/state/lacia/serve.log` で読めます。自動起動をやめるときは `make autostart-off` を実行してください。

確認待ちのタスクや会議をMacの通知で受け取りたい方は、`make notifier` を実行してください。通知アプリの準備には、Xcodeのコマンドラインツールが必要です。

初期設定では、毎朝5時から正午までの間に、依頼を受ける窓口の手が空くと、サーバーが新しい会話に切り替えます。時刻は記録のタイムゾーンに従います。時間帯を変えるときや、自動切り替えを止めるときは、`~/.config/lacia/serve.conf` の `window-rollover` を編集してください。`make install` をやり直しても、この設定ファイルはそのまま使います。

## 決まった時刻に動かす

1台のMacで使う場合、定期タスクはサーバーに設定したCodexかClaude Codeで動きます。[朝の確認の記入例（S0001）](areas/personal/routines/S0001/routine.md)は、最初は停止しています。確認する対象と手順を書いてから、動かしたい時刻を指定してください。たとえば、毎朝8時に動かすには、定義の冒頭を次のようにします。

```markdown
---
id: S0001
title: 朝の確認
daily: "08:00"
output: matters
conversation: side
enabled: true
---
```

`lacia schedules` で、それぞれの定期タスクが有効かどうかと、有効なものの実行時刻を確かめられます。Macがスリープ中に実行時刻を過ぎた回は、スリープから戻ったあとに1回にまとめて実行します。

ひな形に付属する定期タスクの番号は `S0001` と `S0002` です。ご自分で初めて定期タスクを作るときは `S1001` を使います。2件目からは、すべての領域で使っている `S1001` 以降の最大番号に1を足してください。ディレクトリー名と定義の `id` には同じ番号を書きます。通常のタスクを作るときは、`lacia task new` が既定で `T1001` から番号を付けます。

[作業用のファイルを点検する定期タスク（S0002）](areas/personal/routines/S0002/routine.md)は、毎日10時にMacで動く設定です。[片づける手順](areas/personal/procedures/local-storage.md)に沿って `local/` を点検し、整理したあとも上限を超えるときだけ対応をお願いします。上限はリポジトリーごとに10 GiBです。`.lacia/local-storage.json` の `limit_gib` で変えられます。

別の端末で定期タスクを動かすときは、その端末をサーバーに登録し、定義に `to: local-codex` のように宛先を書いてください。特に、Mac以外でサーバーを動かす方は、S0002をいったん `enabled: false` にして、Macを実行先に設定してから有効にしてください。端末の登録と通知アプリの設定は、本体のソースにある `docs/design/schedules.md` の「実行先を選ぶ」で読めます。

## 置いてあるもの

| 場所 | 中身 | 書く人や更新の方法 |
| --- | --- | --- |
| `LACIA_SOURCE` | 本体のソースの取得先 | ひな形の更新で変わります |
| `LACIA_VERSION` | 取得する本体のコミット | ひな形の更新で変わります |
| `AGENTS.md`、`CLAUDE.md` | 会話を始めるときに読む決まりの案内 | そのまま使います |
| `rules/local.md` | このリポジトリーだけの決まり | ご本人とレイシア |
| `.lacia/config.json` | 領域、ご本人の呼び名、記録のタイムゾーン | ご本人 |
| `.lacia/serve.conf` | 画面や伝言に表示するプロファイル名、予定の連携の設定 | ご本人 |
| `.lacia/calendars.json` | 予定を読むカレンダーの一覧 | `lacia init` で作り、ご本人が編集します |
| `memory/` | 基本の情報と好み、アカウント、いまの状況など | ご本人とレイシア |
| `tools/` | `make` が使うスクリプト | そのまま使います |
| `areas/<領域>/routines/` | 決まった時刻に動かす仕事 | ご本人とレイシア |
| `areas/work/`、`areas/personal/` | 領域ごとのタスク（`tasks/`）、プロジェクト（`projects/`）、知識（`knowledge/`）、手順（`procedures/`） | ご本人とレイシア |

共通の決まりは `lacia rules` で読めます。文章の書き方は `lacia rules writing` に、話し方と返事の例は `lacia rules voice` にあります。わたしが何を気にかけ、どんなことをしてみたいと思っているかは、[わたしのこと](memory/self.md)に書いています。

共通の決まりを置き換えるときは、`rules/<名前>.md` に同じ名前の文書を置いてください。共通の文書の末尾に決まりを足すには、`rules/<名前>.local.md` に書いてください。

`lacia doctor` を実行すると、記録を読み取り、誤りやお知らせを表示します。

## 更新

ひな形を取り込む前に、ご自分の `.lacia/config.json` の `format` を確かめてください。すでに2なら、下の「ひな形の変更を取り込む」へ進めます。

### 形式1の記録を移す

`format` が1なら、先に定期タスクを各領域の下へ移します。更新後のひな形を別のディレクトリーに用意し、そこで `make binary` を実行すると、移行に使う版の `lacia` を入れられます。

`schedules/` に以前の予約の定義が残っていれば、先に固定のIDを使う定期タスクに移してください。詳しい手順は、本体のソースにある `docs/design/records.md` の「形を移す（`lacia migrate`）」で読めます。

同じ記録を使うサーバーと端末に対応版が入ったら、サーバーを止めます。ご自分の記録のリポジトリーで `git status --short` に何も出ないことを確かめ、`lacia migrate --dry-run` を実行してください。表示された定期タスクの番号と移動先を確かめてから、`lacia migrate` で移します。最後に `lacia schedules` と `lacia doctor --links` で結果を確かめ、変更をコミットしてください。

### ひな形の変更を取り込む

ご自分の記録のリポジトリーで、次のコマンドを実行してください。`git remote add` は最初の1回だけです。

```sh
git remote add template <ひな形のアドレス>
git pull template main
make install
```

ご自分のリポジトリーとひな形で同じ箇所を変えていると、取り込みが衝突することがあります。手元の記録や設定を残して、ひな形の変更を取り込んでください。

以前のひな形の定期タスク（`S1001` や `S1016`）をすでに使っている方は、その番号と履歴を引き継いでください。ひな形を取り込んで同じ仕事の定期タスクが別の番号で増えたときは、以前から使っているほうだけを動かします。
